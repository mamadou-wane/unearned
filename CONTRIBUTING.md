# Contributing

Unearned is in early development and has no code yet. For now, the most useful contributions are corrections to the documentation and discussion of the planned experiment.

## Reporting a bug

Open an issue using the bug report template. A useful report includes:

- the exact commands or steps that reproduce the problem,
- what you expected and what happened instead, with the full error output,
- the commit you tested and any relevant environment details, such as the operating system, Python version, or hardware.

Do not put details of a security vulnerability in a public issue. Instead, open an issue asking for a private contact and leave the details out.

## Proposing a change

Open an issue to discuss a substantial change before you implement it. Substantial changes include a new component, a new dependency, and any change to how the experiment is run or measured. Small fixes, such as a typo, a broken link, or a bug with an obvious fix, can go straight to a pull request.

## Pull requests

Keep each pull request focused on one change, and keep refactoring or reformatting separate from behavior changes.

Check that the change does what it claims before you open the pull request. In the description, list the exact commands you ran with their results, and name any checks you skipped and why. The repository has no automated checks yet, so for now describe the manual checks you performed.

## Provenance and AI-assisted contributions

Only submit work you have the right to contribute. Identify any third-party code, data, or model output you include, along with its source and license.

AI-assisted contributions are welcome and are held to the same expectations as any other contribution. You are responsible for the correctness of the change, should be able to explain it, and must not include test results or measurements that you did not run.
